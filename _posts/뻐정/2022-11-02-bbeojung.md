# 1. 배경

## 1-1) 시장의 중요성

![슬라이드3](https://user-images.githubusercontent.com/84084372/199404453-771b5c41-098c-4e74-a1da-cc0b15c1088f.JPG)

광주광역시 빅데이터 통합 플랫폼에 따르면, 2022년 8월 기준 약 89.7%가 버스를 이용하는 것으로 나타났습니다. 또한, 광주광역시의 버스 분담률은 근 10년간 80% 이상을 유지하고 있습니다. 이런 상황을 봤을 때, 광주 시민들에게 버스는 중요한 이동수단임을 알 수 있습니다. 이에, 버스 이용과 관련한 정확한 수요 예측과 다양한 정보 제공이 필수적이라고 생각하였습니다.

<br>

## 1-2) 시장의 문제

![슬라이드4](https://user-images.githubusercontent.com/84084372/199404454-d023fd44-1ded-4aa2-bc20-88ca8d848c19.JPG)

현재 광주광역시는 노선체계나 운영방안 등에 대한 연구와 정보 제공이 활발히 이루어지고 있지만, 버스 노선배치에 필요한 버스 수요 분석이나 이를 활용한 연구는 부족한 실정입니다.
따라서 버스 이용객 정보를 활용하여 더 많은 정보를 버스 이용객 및 기업, 의사 결정론자들에게 제공하여 편의를 주는 게 필요하다고 생각하였습니다. 또한, 버스관련 정보는 정보의 분산화 문제를 가지고 있습니다. 버스 도착 예정정보는 카카오 버스에서, 출발 예정 시간은 광주광역시 버스 운행 정보에서 볼 수 있어 다소 불편함이 있습니다.

<br>

![슬라이드5](https://user-images.githubusercontent.com/84084372/199404457-0c28b808-73cf-461e-a30d-083f7b7f0cfc.JPG)

이런 문제 상황 때문에 저희는 뻐정을 고안하게 되었습니다.

<br>
<br>

# 2. 기능

## 2-1) 뻐정 소개

![슬라이드6](https://user-images.githubusercontent.com/84084372/199404458-222c9dd5-84b9-458f-bba0-79f360fe1edf.JPG)

뻐정은 앤비디아 객체탐지 모델과 버스 수요 예측 모델 및 광주광역시 BIS가 결합하여 탄생한 통합 플랫폼입니다. 기존에 광주광역시가 제공한 버스 출발, 도착 예정 정보와 더불어 정류장별 수요 예측을 통해 시민들의 버스 이용 편의를 극대화하고 배차간격, 노선 체계 등의 결정과 같은 의사결정에 도움을 주는 플랫폼입니다.

<br>

## 2-2) 뻐정의 기능

![슬라이드7](https://user-images.githubusercontent.com/84084372/199404462-378b5f45-2c79-4c16-8806-4a57a9ca3f00.JPG)

뻐정의 기능으로는 크게 5가지가 있습니다.

- **첫째, 특정 버스 예상 승차 수요 예측**

  저희가 자체적으로 빌드한 머신러닝 모델을 사용하여 특정 버스의 시간별 예상 수요를 사용자에게 서비스합니다.

- **둘째, 실시간 정류장 혼잡도 확인**

  실시간으로 정류장에 사람이 얼마나 있는지 파악하여 실시간 정류장 혼잡도 정보를 제공합니다. 차후에 광주광역시의 승인을 받아 정류장마다 cctv를 설치하여 rtsp 통신을 통해 실시간 영상을 받아올 계획입니다.

- **셋째, 정류장 검색 및 찾기**

  다양한 검색 기능을 통해 사용자가 원하는 정류장을 쉽게 찾을 수 있습니다.

- **넷째, 버스 정보 제공**

  마지막으로, 광주 BIS API를 사용하여 버스의 도착 예정시간과 운행 시간표 정보를 제공합니다.

<br>
<br>

# 3. 사용 기술

위 기능을 구현하기 위해 저희는 총 세가지의 기술을 사용하였습니다.

## 3-1) 버스 수요 예측 ML Model

![슬라이드8](https://user-images.githubusercontent.com/84084372/199404466-2ab32795-a97c-4179-a866-5a3a31ab2810.JPG)

버스 수요 예측 ML 모델에 대한 기술 설명입니다.

### 3-1-1) 데이터 및 EDA과정

![슬라이드9](https://user-images.githubusercontent.com/84084372/199404469-ddef4775-967d-4e9f-bc80-38784a995f5f.JPG)


데이터는 왼쪽의 표에 나와있는 데이터를 사용하였습니다. EDA 과정에서는 요일별로 탑승 인원이 특정한 패턴을 나타내는 것을 확인하여 weekday에 대하여 onehot encoding을 진행하였습니다. 또한, 광주광역시 버스 이용객은 상위 약 20개 정도의 정류장에 치우쳐있어 해당 정류장들을 지도에 마킹했더니 8개 그룹으로 나누어지는 것을 확인하였습니다. 이에, 8개의 주요 정류장들 간의 거리를 feature로 추가해주었습니다.

<br>

### 3-1-2) Train Feature

![슬라이드10](https://user-images.githubusercontent.com/84084372/199404473-1d18a6e9-e766-4e1f-8fcf-212391b388ee.JPG)

저희가 사용한 Train Feature는 거리, 인구, 통계량, 혼잡도 ,주말, 기상청 데이터, 요일 Feature 입니다.

### 3-1-3) 예측 모델의 결정계수 및 RMSE 값 변화 그래프

![슬라이드11](https://user-images.githubusercontent.com/84084372/199404475-ce49d577-e30c-42ef-b748-7ee17127ee58.JPG)

다음으로는, 예측 모델의 결정계수 및 RMSE값 변화 그래프입니다. 타겟 데이터는 노이즈가 심해 이런 노이즈에 가중치를 부여하는 RMSE를 모델의 평가기준으로 사용해주었습니다. Feature를 순차적으로 누적해서 넣었을 때, error는 줄어들고, 결정계수는 높아지는 것을 확인할 수 있습니다. 즉, 추가한 feature들이 효과가 있음을 증명합니다.

### 3-1-4) 앙상블 알고리즘

![슬라이드12](https://user-images.githubusercontent.com/84084372/199404478-4feaade6-ae75-4704-993d-10d29358551b.JPG)

최종 학습모델 선택 과정입니다. 모델의 대략적인 성능파악을 위해 초기 모델로 Random Forest를 사용하였습니다. 이때 학습 시간은 30분 이상이 소요되었고, RMSE 값은 3.11이 나왔습니다. 그래서 저희는 학습 시간을 단축시키고, score를 향상시켜야 한다고 판단했습니다. 먼저, 모델의 스코어를 높이기 위해 부스팅 알고리즘을 선택하였습니다. 부스팅 알고리즘은 배깅 계열 알고리즘보다 스코어는 높지만 학습 속도가 느리다는 단점이 존재하여 부스팅 중에서도 가볍고 학습시간이 빠른 Light GBM을 최종 모델로 선택하였습니다. 그 결과 학습 속도는 열 다섯배 빨라졌고, error는 약 20% 감소하였습니다.

### 3-1-5) 하이퍼 파라미터 튜닝

![슬라이드13](https://user-images.githubusercontent.com/84084372/199404480-b4630c3a-98a0-4dee-a0db-3c3719103488.JPG)

하이퍼 파라미터 서치 알고리즘으로는 random search를 사용하였습니다. Bayesian Optimization이라는 더 좋은 대안이 있었지만, 이는 병렬처리가 불가하고 Gird, Random search에 비해 계산이 복잡하다는 단점이 있었습니다. 또한, BO는 실수형 파라미터에 대해서만 적용이 가능한데, LGBM은 정수형/범주형 파라미터도 존재하였습니다. 따라서 컴퓨팅 리소스의 제약으로 Random search를 최종 서치 알고리즘으로 채택하였습니다.

<br>

## 3-2) 실시간 객체 탐지 모델

![슬라이드14](https://user-images.githubusercontent.com/84084372/199404482-7b1eff58-8373-467b-9dd9-e65bf7f5048c.JPG)

Real-time Object Detection 모델에 대한 기술 설명입니다.

### 3-2-1) Inference 과정

![슬라이드15](https://user-images.githubusercontent.com/84084372/199404485-fd1f1a7a-2660-49e3-a5fc-ea62b09cb6a3.JPG)

coco 데이터셋으로 pre-train 된 ssd 네트워크 모델을 객체 탐지 모델로 채택하였습니다. ssd 네트워크란, 기존 object detection 모델의 정확도-추론시간 trade-off 문제를 해결한 객체탐지 모델이며, 이 모델의 real-time 추론을 위해 2가지의 최적화를 해주었습니다. 먼저, real-time 추론을 위해서는 모델이 1초에 30번 정도 추론이 가능해야 합니다. 하지만, SSD 모델로는 그 정도의 추론 속도가 나오지 않아 TensorRT로 변환해주는 작업을 해주었습니다. 이 중, 추론에 직접적으로 필요한 Engine부만 떼어서 사용하였으며, GPU에 Tensor들을 올려 커널 연산을 해주었습니다. 이 때, CUDA Stream을 사용해 비동기적으로 device에 memory를 카피해줌으로써 병렬연산을 가능케하여 추론 속도를 단축하였습니다.

### 3-2-2) TensorRT 추론 성능 시각화

![슬라이드16](https://user-images.githubusercontent.com/84084372/199404487-e1e7a5fd-5309-4227-83d6-159e376ba325.JPG)

다음은 TensorRT의 추론 성능을 시각화 한 자료입니다. 기존 ssd 모델 대비 연산속도는 약 24배정도 빨라졌으며, Precision Reduction에 따른 confidence loss는 거의 존재하지 않는 것을 확인하였습니다.

### 3-2-3) 다양한 화각 사용

![슬라이드17](https://user-images.githubusercontent.com/84084372/199404488-dc34b6f2-f6c5-4730-8b2f-9ae1b11be4a5.JPG)

이 기술을 실무에서 활용하기 위해서는 객체가 장애물 또는 사람에 가려져서 인식되지 않는 문제를 해결해야 합니다. 이를 해결하기 위해 시범 정류장에 다양한 화각의 cctv를 설치하여 각 화각의 데이터셋을 확보하고, 모델 파인튜닝 및 블랜딩 할 예정입니다.

### 3-2-4) 시연 영상

오른쪽 화면의 좌측 상단을 보시면, 사람이 실시간으로 카운팅되는 것을 확인할 수 있습니다. 이해를 돕기 위해 바운딩 박스와 스켈레톤을 객체에 표시해 주었습니다.

# 4. 결론
## 4-1) 기대효과

![슬라이드21](https://user-images.githubusercontent.com/84084372/199404497-5b8c659e-24d8-4a5b-b92b-89f2c00b9465.JPG)

뻐정의 기대효과는 다음과 같습니다. 먼저, 시간대별 버스 수요를 정확히 예측하여 수치화된 데이터를 제공해 보다 효율적인 노선 체계를 설계할 수 있습니다. 이는 버스 탑승객을 위한 최적의 서비스 제공이 가능하게 합니다. 둘째, 각종 이벤트 및 행사를 위한 최적의 시간대와 장소 예측 정보를 제공하여 빠른 의사결정에 도움을 줄 수 있습니다. 이는 시간과 비용을 감소시켜 경제적 이득을 얻게 합니다. 셋째, 기존의 버스 출발 정보와 도착 정보 뿐만 아니라 시간대별 버스 정류장의 밀집도 예측 등의 추가적 정보를 제공함으로써 정보의 비대칭을 해소할 수 있습니다.

## 4-2) 활용방안

![슬라이드22](https://user-images.githubusercontent.com/84084372/199404498-08cda0d0-ec81-4574-b003-2d0e61ceb620.JPG)

더 구체적인 사례를 들어 설명하겠습니다. 첫째, 선거철 유세장소 선정에 관한 정보를 제공할 수 있습니다. 유세장소를 선정할 때는 사람이 많은 곳을 선점하는 게 유리합니다. 이때 뻐정을 통해, 특정 시간 수요가 많은 정류장 근처에서 유세 활동을 한다면 홍보에 효과적일 것입니다. 둘째, 광주광역시와의 제휴를 통해 경제적 이익을 얻을 수 있습니다. 버스 전광판에 버스 정류장의 수요를 노출시켜 시민들에게 편의를 제공할 뿐만 아니라 제휴를 통해 수익을 창출할 수 있습니다. 셋째, 다람쥐 버스 운행입니다. 2017년부터 서울에서는 혼잡한 구간만 반복 운행하는 다람쥐 버스를 운행하고 있습니다. 뻐정을 이용해 혼잡 구간을 예측하여 노선을 개편해 운행한다면 광주 시민들에게도 편의를 제공할 수 있을 것입니다.

# 5. 예상질문 QnA

## 5-1) ML 파트

### 5-1-1) 데이터는 얼마나 사용했나요? / 따로 validation 데이터를 만들었나요?

총 데이터 : 200만개 중

- train : 120만 (60%)
- valid : 40만 (20%)
- test : 40만 (20%)

개를 사용하였습니다.

### 5-1-2) 따로 Feature Importance도 확인해보셨나요?

요약 통계량에 대해서는 Feature Importance가 높은 상위 5개의 통계량만 사용. 나머지 피쳐는 모델에 Feature들을 하나씩 추가해봐서 성능 올라가는 것만 확인해 보았습니다.

### 5-1-3) 모델이 오버피팅된 건 아닌지 확인해보셨나요?

평가에 사용된 test 데이터는 trian 과정에 전혀 개입하지 않은 완전히 새로운 데이터입니다. 따라서 오버피팅되지 않았다고 판단하였습니다.

### 5-1-4) 앙상블 알고리즘이라는 것이 무엇인가요?>

여러개의 머신러닝 모델을 이용해 최적의 답을 찾아내는 기법입니다.

### 5-1-5) 배깅과 부스팅 알고리즘이 뭔가요?

- 배깅 : 하나의 알고리즘 내에서 여러개의 샘픔을 중복 생성하여 결과를 도출하는 기법

- 부스팅 : 이전 오차를 보완해나가며 가중치를 부여하는 기법 -> 정확도가 높으나 병렬처리가 안되므로 학습 속도가 느림

### 5-1-6) 하이퍼 파라미터 튜닝 시, grid search를 사용하지 않은 이유?

그리드 서치가 최적의 효율을 내기 위해서는 해당 모델의 하이퍼 파라미터에 대한 도메인 지식이 있어야합니다. 하지만, LGBM에 대한 도메인 지식이 없었기 떄문에 random search를 최종 서치 알고리즘으로 선택하였습니다.

## 5-2) Object Detection 모델 파트

### 5-2-1) 모델을 직접 파인튜닝하셨나요?

coco 데이터셋으로 pre-train된 ssd 모델을 기본 모델로 사용하였습니다. 저희는 이 ssd 모델을 real-time으로 사용할 수 있게 optimization 해주었습니다. 차후에 정류장 관련 데이터셋을 구한다면, 해당 데이터셋으로 파인튜닝 시켜 줄 계획입니다.

### 5-2-2) SSD 네트워크가 어떻게 기존의 trade-off 문제를 해결하였나요? or 성능을 개선시켰나요?

기존 obj detection 모델들은 바운딩 박스 생성 후, 이를 재조정하는 step이 필요했습니다. ssd는 이러한 재조정 스탭을 없앰으로써 추론 속도를 향상시킬 수 있었습니다. 또한, convolution 후 feature map을 생성하는 과정에서 이미지 크기가 줄어드는 점을 이용하여 정확도도 올릴 수 있었습니다.

### 5-2-2) YOLO도 ssd의 좋은 대체제가 될 수 있었을텐데 ssd를 사용한 이유?

YOLO의 초기 버전들은 속도는 빠르지만 정확도가 낮은 것으로 알고 있습니다. 또한, SSD 모델이 obj detection 분야에서 뛰어난 성능을 내는 것으로 알고 있었기 때문에 SSD 모델을 최종 모델로 선택하였습니다. 아직 해당 기능은 준비 단계이기 때문에 차후 해당 모델을 개선할 때, YOLOv5 이상의 모델도 고려해볼 것 같습니다.

### 5-2-3) TensorRT가 뭔가요?

앤비디아에서 만든 최적화 tool이며, 자사 GPU 사용 시 커널이 최적의 연산을 할 수 있게 도와줍니다.

### 5-2-4) TensorRT가 어떻게 연산속도를 저렇게 개선할 수 있었나요?

1. 모델 내부 python 코드를 c++로 컨버팅함으로써, 모델을 간단하고 가볍게 만들어주었으며,

2. FP32에서 FP16으로 precision reduction을 시켜주었습니다. 이 때, 앤비디아 자체 기술을 사용하여 컨피던스 로스를 최소화 합니다.

### 5-2-5) 그래서 CUDA Stream이라는 게 정학히 뭔가요?

NULL Stream(널스트림)을 사용하여 mem copy시, 명령들은 동기적으로 수행되기 때문에 중간중간 연산 없이 노는 부분이 생깁니다. 하지만, CUDA Stream(쿠다 스트림)을 사용하면, 명령을 비동기적으로 수행하기 떄문에 노는 부분 없이 병렬적으로 명령을 수행할 수 있습니다. 자세한 사항은 제 기술블로그를 참고하시면 됩니다.

- **Reference**

  <https://on-jungwoan.github.io/dl/cuda_stream/>


### 5-2-5) 3-2-2의 그래프는 뭘 나타내는 건가요?

- 추론속도 그래프 : 이미지 한 장을 연산하는데 걸리는 시간을 ms(1/1000초)로 나타내준 것입니다. 맨 위 파란색이 원본모델, 초록색이 trt engine(텐서알티 엔진)입니다

- Confidence Loss 그래프 : 선별 사진 500장 대한 각 모델의 추론 결과 중 일부입니다. FP32에서 FP16으로 precision reduction이 있었으나, Confidence Loss는 거의 나타나지 않습니다.
