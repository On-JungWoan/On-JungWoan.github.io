<역사>
- perceptron : wx+b와 유사한 함수 사용, but 출력값이 1 or 0, W 업데이트하는 업데이트 룰이 존재(backprop과 유사)

FC Layer(fully connected layer) : 어떤 벡터를 가지고 연산을 함
ex) 32x32x3의 이미지가 있으면, 이를 3072x1의 벡터로 쭉 핀 다음 W와 내적을 하여 activation을 얻는다. (이게 이 layer의 출력임) -> 뉴런의 한 값(이 예시는 10개임)

FC layer와 convolution layer의 차이?
fc layer가 입력 이미지를 길게 쭉 폈다면, 이제는 기존의 이미지 구조를 그대로 유지하게 됨.
그리고 작은 필터가 우리가 가진 가중치가 되고(예시에서는 5x5x3 필터), 이 필터가 이미지를 슬라이딩 하며 공간적으로 내적을 수행하게 됨.

필터?
하나의 필터는 아주 작은 부분만 취하지만(32x23 중 5x5), 필터의 깊이 입력의 전체 깊이를 취함. 
그리고 필터를 이미지의 특정 부분에 놓고, 필터의 w와 이에 해당하는 이미지의 픽셀을 곱해줌.
w^T(w를 행벡터로 만들어주기 위해 transpose해준 것)x + b의 연산을 함.

어떻게 슬라이딩?
colvolution운 이미지의 좌상단부터 시작. 그리고 필터의 모든 요소를 가지고 내적을 수행하게 되면 하나의 값을 얻게됨. 이 값들은 다시 output activation map의 해당하는 위치에 저장 그리고 슬라이딩. 이 때, 출력 행렬의 크기는 슬라이드를 어떻게 하느냐에 따라 다르게 됨(기본적으로는 하나씩 연산 수행).
-> 하나의 필터를 가지고 전체 이미지에 conv 수행하면 activation map이라는 출력값을 얻게 됨.
(보통 convolution layer에서는 여러개의 필터를 사용한다. 왜냐하면 필터마다 다른 특징을 추출하고 싶기 때문이다.)

햔 layer에서 원하는 만큼 여러개의 필터를 사용가능ㅎ ㅏ다. 만약 5x5필터가 6개 있다면 총 6개의 activation map을 얻게 될 것이다. 그러면 차원은 6x28x28이 된다.

CNN은 이런식의 convolutional layer들의 연속된 형태. 각각을 쌓아 올리게 되면, 간단한 linear layer로 된 neural network가 된다. 그 사이사이에 ReLU와 같은 activation function을 넣을 것임. conv-ReLU가 반복(가끔은 pooling도 들어감). 각 layer의 출력은 다음 layer의 입력이 된다.

각 layer는 여러개의 필터를 가지고 있으며, 각 필터마다 각각의 출력 map을 만드는데, 여러 layer를 쌓다보면 결국 각 필터들이 계층적으로 학습하게 되는 것을 알 수 있음. 다음은 이미지가 어떻게 생겨야 해당 뉴련의 활성을 최대화시킬 수 있는지를 시각화한 것이다(그리드의 각 요소는 각 뉴런의 활성을 최대화시키는 입력의 모양을 나타낸 것). 가령, 앞쪽에 있는 필터들은 edge와 같은 low-level feature를, mid-level을 보면 코너, blob등 좀 더 복잡한 특징을, high-level features를 보면 좀 더 객체와 닮은 것들이 출력으로 나옴


activation map : 필터가 만든 출력값(5x5 필터들을 시각화 한 것)

# CNN이 어떻게 수행되는가?

필터를 오른쪽으로 한칸 움직임 -> 값하나 얻기

N(차원), F(필터 사이즈)라면,
-> ouptut size : (N - F) / stride + 1

# zero-pad
이미지의 가장자리에 0을 채워 넣는 것
이렇게 하면, 모서리가 상대적으로 필터에 덜 적용되는 것을 막을 수 있다.
또한 위 상황처럼 필터가 가장자리까지 닿지 않는 경우, 필터가 닿지 않는 모서리 부분에서도 값을 뽑을 수 있게 됨
-> ouptut size : (N+2 - F) / stride + 1
zero padding 말고도 mirror나 extend라는 방법도 있음
또한, layer를 거치면서도 입력 사이즈를 유지할 수 있음.
가령 7x7 필터를 연산한다고 하면, 출력의 사이즈는 입력보다 작아진다.
출력 사이즈를 입력 사이즈와 동일하게 유지하고 싶은 경우, padding을 한다.
만약 layer가 여러겹 쌓였는데 zero-padding을 하지 않으면, layer를 거칠수록 activation map은 점점 줄어들어 엄청 작아지게 될 것임(일부 정보의 손실).
줄어드는 이유 : 매번 각 코너에 있는 값들을 계산하지 못하기 때문

여기서 명심해야 할 점은, activation map의 depth는 우리가 가진 필터의 수이다.
왜냐하면 각 필터가 입력의 모든 depth에 내적을 수행하기 때문이다.


# 일반적인 방법

33 : 1
55 : 2

{(32+2x2-5)/1} + 1 = 32 -> 32x32
전체 필터의 갯수는 10개이므로 32x32x10의 activation map이 나옴

# stride에 대한 직관?

우선, stride는 크게 가져갈 수록 출력이 점점 작아짐.
이미지를 다운 샘플링한다는 점에서 pooling과 비슷하지만, 그 둘은 확실히 다르고 풀링보다 더 좋은 성능을 보이기도 함
pooling 처럼 다운 샘플링하는 동일한 효과를 얻으면서도 더 좋은 성능을 낼 수 있다.
또한, activation map의 사이즈를 줄이는 것은 추후 모델의 전체 파라미터 갯수에도 영향을 미친다.
가령, conv layer 마지막에는 fc layer가 있는데, fc layer는 conv의 출력 모두와 연결되어 있다.
따라서 conv layer의 출력이 작을수록 fc layer에서 필요한 파라미터의 수가 더 작아진다.
이러한 파라미터의 수, 모델 사이즈, overfitting과 같은 것들에는 다양한 trade-off가 존재한다.
따라서 상황에 맞게 stride를 선택

# Pooling layer

max pooling이 일반적으로 사용됨
representation들을 더 작고 관리하기 쉽게 해줌(Downsampe)
왜 작게 만드냐? -> 작아지면 파라미터의 수가 줄기 때문, 또한 일종의 공간적인 불변성을 얻을 수도 있음
가령, 224x224x64인 입력이 있다면 이를 112x112x64로 공간적으로 줄여줌
but, 중요한 점 : depth에는 아무짓도 하지 않음(변화x)

pooling에도 필터 크기를 정해 얼마만큼의 크기를 한번에 묶을지 정할 수 있다.
stride를 정해 conv layer가 했던 것처럼 슬라이딩 한다.
대신 내적을 하는 것이 아니라 최대값을 찾는다(max pooling의 경우)

또한 Pooling은 기본적으로 (영역이) 겹치지 않게 한다.

왜 주로 max pooling을 사용하나?

우리가 다루는 값들은 얼마나 이 뉴런이 활성되었는지를 나타내는 겂들임 -> 즉, 필터가 각 위치에서 얼마나 확성되었는지?
따라서 max pooling은 그 지역이 어디든 어떤 신호에 대해 얼마나 그 필터가 활성화되었는지를 알려준다고 알 수 있음
우리가 인식에 대해 생각해보면 어느 정도의 직관을 얻을 수 있는데, 그 값이 어디에 있었다는 것 보다는 그 값이 얼마나 큰지가 중요한 것임
따라서 max pooling을 주로 사용함.

# pooling layer의 design choice?

우선, 입력의 디자인이 W(width), H(height), D(depth)면, 이를 통해 filter size를 정해줄 수 있음
또한, 여기에 stride까지 정해주면, 앞서 conv layer에서 사용했던 수식을 그대로 이용해서 design choice를 할 수 있다[ (W - Filter Size) / Stride + 1 ]

한 가지 특징이 있다면 pooling layer에서는 보통 padding을 하지 않는다
why?
downsampling을 하고 싶고, conv 때처럼 코너의 값을 계산하지 못하는 경우 없음
따라서 pooling 할때는 padding 고려안해도 됨

가장 널리 쓰이는 필터 사이즈는 2x2, 3x3이고 보통 stride는 2로 함.
3x3일때도 보통 stride는 2x2로 하는 편

downsampling을 하고 싶을때는 pooling을 섞어주기만 하면 됨.
