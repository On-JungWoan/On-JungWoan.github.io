### activation functions

지난시간에 봤던 layer : 데이터 입력이 들어오면 가중치와 곱합
FC, CNN 등등 -> 그리고 나서 활성함수 (비선형 연산)을 거치게 됨.

- sigmoid

1/(1+...) : 각 입력을 받아서 그 입력을 0~1 사이의 값이 되도록 해줌.
입력값이 크면 출력은 1에 클 겂이고 그렇지 않으면 0
뉴런의 firing rate를 saturation 시키는 것으로 해석시킬 수 있어서 인기가 많았음(0~1사이의 값이 firing rate)

문제점
1. saturation 되는게 gradient를 없앤다.

sigmoid gate를 computational graph에서 확인.
backprop에서 gradient는?
sigmoid gate의 local gradient는 dL/sig x sig/dx가 되고, 이것이 앞단으로 계속 전파될 것임.

그럼 만약 x가 -10이라면?
x=-10일 때 dsig/dx = 0이므로 gradient가 0이 됨(sigmoid가 flat하기 때문에)

따라서 거의 0에 가까운 값이 backprop 됨
이 부분에서 gradient가 죽어버리게 되고 밑으로 0이 계속 전달되게 됨.

x가 0이면?
이 구간에서는 잘 동작할 것이고 그럴싸한 gradient를 얻게 됨

x가 10이면?
역시 0 -> sigmoid가 flat하기 때문에 gradient를 다 죽여서 잘 흐르지 ㅇ낳게 ㄱ됨.

2. sig의 output이 zero-centered하지 않ㅇ므

뉴런의 입력이 항상 양수인 경우?
이 x는 어떤 가중치와 곱해져서 활성함수를 통과하게 됨.
그럼 W에 대한 gradient는?
전부 양수이거나 전부 음수가 됨

gradient = dL/d활성함수 x d활성함수/dW인데,
d활성함수/dW는 그냥 X임
따라서 gradient의 부호는 그저 위에서 내려온 gradient의 부호와 같아질 것임
-> W가 모두 같은 방향(파라미터 업데이트 시, 다 같이 증가 or 다 같이 감소)으로 움직이게 될 것임.

그래프와 같이 4분면 중 gradient가 이동할 수 있는 방향은 2개 사분면밖에 안됨
만약 이론적으로 가장 최적의 W 업데이트가 저 파란색 화살표이고, 빨간 화살표의 시작부분부터 시작한다고 가정해보자.
파란색 방향으로 gradient가 내려갈 수 없으므로 여러번 gradient 업데이트를 해야 함.(gradient가 움직일 수 있는 방향으로) -> zero-mean data를 원하는 이유

3. exp()로 인해 계산 비용이 크다.

그리 큰 문제는 아니지만, 굳이 문제로 뽑자면 이렇다

## tanh

sigmoid와 유사하지만 -1~1범위
가장 큰 차이점 : zero-centered이지만, saturation 때문에 gradient가 죽음
(여전히 양 끝 값에서 평평해지는 구간 존재)

## ReLU

상당히 자주 쓰임
f(x) = max(0, x)
입력값이 음수면 0이 되며, 양수면 입력값 그대로를 출력한다.

ReLU는 양의 값에서는 saturation 되지 않음(완만해지는 부분 업승ㅁ) -> 가장 큰 장점
계산 효율이 매우 뛰어남(지수항이 없음, 단순 max연산 -> 계산이 매우 빠르다)
sig나 tanh보다 6배정도 더 빠르다
생물핮적 타당성도 relu가 sigmoid보다 더 크다.
실제 뉴런의 입/출력값은 isgmoid보다 relu스러움

문제

1. zero-centered가 아님 -> relu가 가진 이슈

2. 음의 경우에서 saturation이 되지 않음

x=-10이면 gradient 10
x=10이면, 선형영역
x=0이면, 여기서 정의되지는 않았지만 실제로는 0임

-> 따라서 ReLU는 기본적으로 gradient의 절반을 죽여버리는 셈임

dead relu?

1. w의 시작점이 data cloud(train data)에서 너무 멀리 떨어져있는 경우
어떤 데이터 입력에 대해서도 activate되지 않음, backprop이 일어나지 않음
activate되지도, update되지도 않음

2. learning late가 너무 큰 경우
가중치가 날뛰어서 ReLU가 데이터의 mainfold를 벗어나게 됨
처음에는 학습이 잘 되다가 갑자기 죽어버림

실제로 학습을 다 시켜놓은 네트워크를 보면 10~20%가량은 dead relu가 되어있음
relu를 사용하고 있다면 대부분의 네트워크가 이 문제를 겪음.
하지만 10~20가량이면 네트워크 학습에 크게 지장이 있지는 않음.

-> 따라서 relu 초기화 시 positive biases를 추가해주는 경우가 있음
update 시 active relu가 될 가능성을 높여줄 수 있지만(도움이 안된다는 의견도 있음)
항상 사용하지 않고 대부분은 zero-biases

## Leaky ReLU

negative regime에서 더이상 0이 아님.
negative에도 기울기를 살짝 줌.
negative space에서 saturation되지 않고, sig, tanh보다 계산도 빠르며, dead relu현상도 없음

## parametric rectifier(PReLU)

negative regime에서 기울기가 존재함은 leaky relu와 비슷하지만, prelu는 기울기가 alpha라는 파라미터로 결정됨
여기서 alpha는 backprop으로 학습시키는 파라미터로 만든 것
활성함수가 좀 더 유연해짐

## ELU

ReLU의 장점을 가져오며 zero-mean에 가까운 출력을 보임
saturation을 갖긴 하지만, 이러한 saturation이 noise에 강하며,
이러한 deactivation이 좀 더 강인함을 줄 수 있다고 주장
ReLU와 leaky relu의 중간정도라고 보면 됨
(leaky relu처럼 zero-mean의 출력을 내지만 saturation의 관점에서 relu와 닮아있음)

## Maxout Neuron

입력을 받아들이는 특정한 기본형식을 미리 정의하지 않음.
대신에 w1와 x내적한 값 + b1, w2와 x내적한 값 + b2의 최대값을 사용함
이 두 함수 중 최대값을 취하는 것임
relu와 le relu의 일반화 된 형태.
maxout은 이 두개의 선형 함수를 취하기 때문
maxout은 선형이기 때문에 saturation되지 않으며 gradient가 죽지 않을 것
그러나 뉴런당 파라미터 수가 두배가 됨(w1, w2를 지니고 있어야 함)

실제로 가장 많이 쓰이고 표준이고 대게는 잘 동작하는건 relu
but learning ratge를 아주 조심스럽게 결정해야 함.
le relu elu maxout등도 써볼 수 있지만 아직은 실험단계
대게는 relu와 relu의 변종들이 잘 동작함
sigmoid(가장 구식)나 tanh보다는 LU 패밀리 계열이 더 잘 동작함

# data preprocessing

가장 대표적인 전처리 과정

1. zero-mean으로 만들기 : 입력값이 전부 positive인 경우의 문제 때문(0이거나 negative인 경우에도 발생)
2. normalize(std로) : 모든 차원이 동일한 범위안에 인게 해줘서 전부 동등한 기열르 하게 함. 이미지는 zero-centering정도만 해줌. 이미지는 이미 각 차원간에 스케일이 어느정도 맞춰져있기 때문이다.

스케일이 다양한 ML 문제와 달리 이미지에서는 normalization을 잘 해줄 필요는 없음

이미지에서 PCA, Whitening등의 전처리는 잘 사용하지 않음
CNN에서는 원본 이미지 자체의 spatial(공간) 정보를를 이용해서 이미지의 spatial structure를 얻을 수 있도로 ㄱ한다

-> 이미지를 다룰때는 기본적으로 zero-mean으로 ㅈ전처리 해줌
평군은 전체 traing data에서 계싼 -> 미니배치 전 한번에 구해놓고 사용하는 것이 좋음, 데이터가 매우 큰 경우 미니배치로 샘플링해서 샘플 평균 사용하는 경우도 있음
네트워크에 들어가기 전에 평균값을 뺴주게 됨
\test time의 이미지에서도 training time에서 계산한 값을 빼줌
일부 네트워크에서는 채널(ex. RGB 채널)마다 평균을 독립적으로 계산하는 경우도 있음(VGGNet - RGB별로 각각 평균을 구함)
채널별로 평균이 비슷할지, 독립적으로 계산해야 할 것인지는 직접 판단해야함

그렇다면 sigmoid의 zero-mean문제를 전처리로 해결 가능?
첫 번째 레이어에서는 해결할 수 있겠지만, 그 다음 layer부터는 동일한 문제를 겪게 될 것이고, 더 깊은 네트워크일 수록 이 문제는 더 시맿짐

# weight initialization

모든 파라미터를 0으로 세팅하면?(모든 가중치가 0이라면?)
-> 모든 뉴런이 전부 똑같은 일을 하게된다(죽지는 않음)
모든 뉴런은 모두 다 같은 연산을 하게되므로, 출력도 모두 같을 것이고 gradient도 같을 것이다. 따라서 모든 가중치가 똑같은 값으로 업데이트 되며, 결국 모든 뉴런이 모두 똑같이 생기게 됨.
-> 모든 가중치를 동일하게 초기화시켰을 때 나타나는 문제 (Symmetry breaking이 일어날 수 없음)

따라서 임의의 작은값으로 초기화 해야함
초기 W를 standard gaussian에서 샘플링 하고 좀 더 작은 값을 위해 스케일링 해준다.
0.01을 나눠 표준 편차를 0.01로 만들어준다.

-> 모든 가중치를 임의의 값으로 초기화 함 (작은 네트워크에서는 symmetry breaking에 충분 but 깊은 네트워크에서는 잘 안될수도 있음)

# 가중치를 좀 더 큰 값으로 초기화 한다면?

가중치의 편차를 0.01이 아니라 1로 한다면?
-> 값들이 saturation될 것임
가중치가 큰 값을 가지므로 tanh의 출력은 항상 saturation될 것임
-> 따라서 gradient는 0(가중치 없데이트x) 출력은 항상 -1이거나 +1이 된다.


=> 적절한 가중치를 얻는 것은 너무 어렵다.
너무 작으면 사라져버리고, 너무 크면 saturation되어 버린다.


# 좋은 방법
## Xavier initialization(Glorot, 2010)

standard gaussian으로 뽑은 값을 "입력의 수"로 스케일링해줌.
-> 입/출력의 분산을 맞춰줌
수식을 통해 직관적으로 이해할 수 있는 것 (입력의 수가 작으면 작은 값으로 나누고 좀 더 큰 값을 얻음)
-> 입력의 수가 작은 경우 큰 가중치를 곱하고, 반대로 입력의 수가 큰 경우 작은 가중치를 곱해 입/출력의 분산을 맞춰줌.

각 레이어의 입력이 unit gaussian(approximately 함)이길 원한다면 이런류의 초기화 기법을 이용해 볼 수 있음
