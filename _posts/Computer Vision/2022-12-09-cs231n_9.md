## LeNet

industry에 아주 성공적으로 적용된 최초의 ConvNet이다. 
LeNet은 이미지를 입력으로 받아, stride=1인 5x5 필터를 가지고 몇 개의 conv layer와 pooling layer를 거침. 그리고 끝단에는 FC LAyer가 붙음. 간단하지만 매우 우수한 성능을 보임

## 2012 : AlexNet

최초의 Larg scale CNN이며, ImageNet Classification Task에서 놀라운 성능을 보여 2012년 Image Classification Benchmark에서 우승한 모델이다. 2012년에 등장한 non-딥러닝 모델을 능가하는 성능을 보여줘 ConvNEt 연구의 부흥을 일으킨 장본인임. CNN기반 최초의 우승 모델이며 이후 수년동안 대부분 CNN 아키텍쳐의 베이스 모델로 사용됨.

기본적으로 conv-pool-normalization 구조가 2번 반복됨. 그 후에 conv layer가 조금 더 붙고 그 뒤에 pooling layer가 있따. 마지막에는 FC-layer가 몇개 있는 구조. 생긴 것만 봐서는 LeNet과 상당히 유사하고 레이어만 더 많아진 것을 확인할 수 있다.

### 크기

ImageNet 기준 input image 크기 : 227x227x3임
AlexNEt의 첫 레이어는 11x11 필터가 stride=4로 96개 존재한다.

#### 첫 번째 Layer CONV1

출력 사이즈 : (227-11)/4 + 1 -> 55x55x96
-> 이유 적어보기 (필터 사이즈. 개수 연관해서)

전체 파라미터 수
(11x11x3 -> 필터 하나)x96 = 35K

#### 두 번째 Layer POOL1

stride=2인 3x3 filter가 있다고 했을 때

출력 사이즈 : (55-3)/2 + 1 -> 27x27x96
pooling Layer는 이미지의 사이즈는 줄이지만, depth는 일정하게 유지

전체 파라미터 수
Pooling Layer에는 파라미터가 없다 -> 헷갈림 주의
파라미터는 우리가 학습시켜야 할 파라미터인데, Pooling layer는 단순히 down sampling의 용도로만 사용되므로 파라미터 필요 없음

나머지 AlexNet Layer도 계산해보기 (도움 많이될 것임)
마지막 FC-Layer는 Softmax를 통과

### 특징

Activation function으로는 ReLU를 사용
Local response normalization layer는 요즘은 잘 사용하지는 앟음(큰 효과 없는 것으로 알려짐)

flipping, jittering, cropping, color norm 등의 data augmentation을 엄청 함
Dropout을 사용했으며, Batch size는 128, SGD Momentum을 optimizer로 사용.
초기 Learning rate는 1e-2로 initialize했으며, val accuracy가 올라가지 않는 지점에서는 학습이 종료되는 시점까지 lr을 1e-10까지 줄였다.(learning rate decay?)
weight decay를 사용했고, 마지막에는 여러개의 모델을 앙상블하여 성능을 향상시킴.

- cf) weight decay란?

  Overfitting 문제를 해결하기 위해서 여러가지 방법이 쓰일 수 있는데, 그 중 한가지가 Weight decay이다. Loss function이 작아지는 방향으로만 단순하게 학습을 진행하면 특정 가중치 값들이 커지면서 위 첫번째 그림처럼 오히려 결과가 나빠질 수 있다. Weight decay는 학습된 모델의 복잡도를 줄이기 위해서 학습 중 weight가 너무 큰 값을 가지지 않도록 Loss function에 Weight가 커질경우에 대한 패널티 항목을 집어넣는다. 이 패널티 항목으로 많이 쓰이는 것이 L1 Regularization과 L2 Regularization이다. Weight decay 를 적용할 경우 위 두번째 그림처럼 Overfitting에서 벗어날 수 있다.

### 다른 conv net과의 차이점

첫 Layer에서 모델이 두 개로 나눠져서 서로 교차하는 것을 확인할 수 있는데, 이는 당시 GPU 메모리의 한계로 인해 레이어를 나눠서 넣었기 때문이다(55x55x96 -> 55x55x48 2개).

conv 1,2,4,5는 같은 GPU내의 Feature Map만 사용하여 48개의 Feature만 사용.
conv 3과 FC 6,7,8은 전체 feature map과 연결되어 있음 -> GPU간의 통신을 하여 이전 레이어의 전체 depth를 가져올 수 있음

### issue

## VGGNet

### 특징

훨씬 깊어졌고, 더 작은 필터를 사용함. -> alex(8), vgg(16~19)
vggnet은 항상 3x3의 아주 작은 필터만 사용한다. 그리고 이는 이웃 픽셀을 포함할 수 있는 가장 작은 필터이다.
이렇게 작은 필터를 유지하며 주기적으로 pooling을 수행하며 전체 네트워크를 구성함.
imagenet에서 7.3%의 top 5 error를 기록함

### 작은 필터를 사용한 이유?

필터의 크기가 작으면 파라미터의 수가 더 작기 때문에, 레이어를 더 많이 쌓을 수 있다.(depth를 더 키울 수 있다). 3x3 필터를 여러개 쌓은 것은 결국 7x7 필터를 사용하는 것과 실질적으로 동일한 receptive field(filter가 한번에 볼 수 있는 입력의 spatial area) 갖는것임.

https://bookandmed.tistory.com/58 여기 설명 읽어보기

-> 7x7 필터와 실질적으로 동일한 receptive field를 가지면서도 파라미터 수는 더 줄일 수 있음 -> 따라서 더 깊은 레이어를 쌓을 수 있게 됨으로써 Non-Linearity를 더 추가할 수도 있게됨

## GoogLeNet == InceptionNet

2014년 classfication challenge에서 우승함
22개의 레이어를 가지고 있고, 매우 깊은 네트워크임.
효율적인 계싼을 하도록 네트워크를 디자인 하였으며, inception module을 여러개 쌓아서 만듦
파라미터를 줄이기 위해 fc-layer를 제거하였음.
파라미터 수는 5M으로, 60M인 alex보다도 적음
그럼에도 불구하고 훨씬 깊음

### inception module

inception module 내부에는 동일한 입력을 받는 서로다른 다양한 필터들이 병렬로 존재함.
이전 레이어의 입력을 받아 다양한 ocnv 연산을 수행하는 것임
각 레이어에서 각각의 출력이 나오게 되는데, 그 출력들을 모두 depth 방향으로 합침.,90
이렇게 합치면 하나의 tensor로 출력이 결정되고, 이 하나의 출력을 다음 레어이로 전달하는 것

#### 계산비용의 문제점

예를 들어, input으로 28x28x256을 받는 inception module을 생각해보자.
각 Layer의 계산 비용을 합치게 되는데, 28x28은 동일하고(spatial dimention을 동일하게 맞춰주기 위해 zero-padding을 해줬음) depth가 점점 쌓이게 된다.
최종적으로 28x28x672가 됨.
inception module의 input은 28x28x256이었으나, output은 28x28x672가 된 것임
spatial dimention이 변하진 않았지만, dimention이 엄청나게 늘어남.
계산량을 전부 더해보면, inception module에서의 전체 연산량은 854M이 된다. -> 매우 많은 연산량
layer를 거칠 떄마다 depth가 점점 늘어나게 됨(256->672->...). 

#### 해결 : bottleneck layer

conv 연산을 수행하기에 앞서 입력을 더 낮은 차원으로 보내는 방법임.
낮은 차원으로 보낸다?

만약 56x56x64의 input img에 1x1 CONV with 32 filters를 사용하면, 
이미지 크기는 그대로 유지한 채 depth를 32로 줄일 수 있다.
-> spatial locatin은 유지한 채 입력의 차원을 더 낮은 차원ㅇ로 projection
-> 이는 input feature map들간의 linear combination(선형결합)이라고 할 수 있음
왜냐? 각 필터는 input image의 channel과 동일한 depth를 가지고 각 채널의 연산 결과를 하나로 합침

주요 아이디어 : 1x1 conv를 사용하여 입력의 depth를 줄인다.

CONV 이전에 1x1 conv가, POOL 이후에 1x1 conv가 추가된 것을 확인할 수 있음
1x1 conv가 bottleneck layers의 역할로 추가되는 것이다.

[계산]
input : 28x28x256 -> 28x28x480
계산량:  854M(no bottle) -> 358M(use bottle)


=> 이를 통해 배울 수 잇는 점 : 1x1 CONV를 사용하면 계산량이 줄어든다.

googlenet은 이러한 inception model을 쌓아올린 것임

### 구조

가중치를 가진 레이어는 총 22개이며, inception moudul은 1x1/3x3/5x5 conv layer를 병렬적으로 가지고 있음. AlexNet 대비 12개 작은 파라미터를 가지고 있음

앞단(stem) : 일반적인 네트워크 구조처럼 conv-pool을 반복
중간 : 조금씩 다른 inception module을 쌓음.
-특이한 점

  중간에 보조 분류기(auxiliary classifier)가 존재
  avgpool, conv, fc등으로 이루어져 있으며, softmax로 1000개의 imagenet class를 구분함
  -> 네트워크의 끝에서 뿐만 아니라 이 두 곳에서도 loss를 계산한다(네트워크가 깊기 때문 : 네트워크가 엄청 깊은 경우에는 그레디언트 신호가 점점 작아지게 되고, 결국에는 0에 수렴할 수 있음 따라서 보조 분류기를 이용해서 추가적인 그레디언트 신호를 흘려줌)
  보조 분류기를 중간 레이어에 달아주면 추가적인 그레디언트를 얻을 수 있고, 중간 레이어의 학습을 도울 수 있음


끝단 : classifier 결과를 출력

FC-Layer를 대부분 걷어냈으나, 성능이 그래도 잘 나오는 것을 확인할 수 있었음.

## ResNet

혁명적으로 네트워크의 깊이가 깊어진 모델
ResNet 아키텍쳐는 152 레이어ㅣ로 엄청나게 깊음(기존의 어떤 네트워크보다 깊음)

-> residual connections라는 방법을 사용
ResNet 하나로 ImageNetm COCO Classification/detection 등 여러 대회 우승

### 기본 Motivation

일반 CNN을 깊고 더 깊게 쌓게되면 어떻게 될까??

  Q) 가령, VGG에 conv pool 레이어를 깊게만 쌓는다고 과연 성능이 더 좋아질까?
  A) NO

  plain CNN에 대해서 56레어어의 test error가 20레이어보다 더 높게 나왔다.
  but training error에서 56레이어가 overfit 할 것으로 예상하였으나, training error도 56레이어가 더 낮았다.
  따라서 test에서 56레이어의 성능이 더 좋지 않은 이유가 overfitting 때문이 아니라는 것을 알게 됨
  
  ⇒ Optimization의 문제로 생각했다. deeper model은 Optimization이 더 어렵기 때문이다.

그렇다면, 우선 더 얕은 모델의 가중치를 깊은 모델의 일부 레이어에 복사한다.
그리고 나머지 레이어는, input을 output으로 그냥 내보내는 identity mapping을 해버림
이런 구성을 하면, Deeper Model의 학습이 제대로 안되더라도 적어도 shallower layer만큼의 성능은 보장됨

-> 이 motivation을 우리가 만들 모델에 녹이려면 어떻게 모델 아키텍쳐를 디자인해야할까?

### ResNet의 아이디어

ResNet의 아이디어는, 레이어를 단순하게 쌓지 않는 것임. Direct mapping 대신에 Residual mapping을 하도록 블럭을 쌓았음. 

-> skip connection에 대한 설명 넣기

F(x)가 residual이다.
residual을 학습시키는 것은 X에 대한 변화량(delta)를 학습시키는 것이다
이는 가설일 뿐이고, residual이 필요 없다는 주장도 있음
그러나 실제로는 ResNet을 사용하면 성능이 좋아지는 것이 fact

### 구조

네트워크 초반은 Conv Layer가 추가적으로 붙음

하나의 Residual blocks는 2개의 3x3 conv layers로 이루어져 있으며, 일반적으로 이렇게 구성해야 잘 동작하는 것으로 알려져 있음.
이 Residual blocks를 매우 깊게(ResEnt은 150layer까지) 쌓아올림
그리고 주기적으로 필터를 2배씩 늘리고 stride 2를 이용하여 down samplng

네트워크 끝에는 FC-Layer가 없는 대신 GAP(Global Average Pooling) Layer를 사용 -> 하나의 Map 전체를 Average Pooling한다. 마지막에는 1000개의 클래스 분류를 위한 노드가 붙는다.

-> 아주 심플하면서도 세련된 모델임.

### Bottleneck Layers

depth는 34, 50, 100까지 늘어나며 논문에서는 ImageNet 문제를 위해 152까지 늘림
이 때, 모델 Depth가 50이상인 경우 Bottleneck Layers를 도입함(GoogLeNet과 유사)
이로인해 3x3 conv의 계산량을 줄이고, 다시 1x1 conv를 추가해서 depth를 다시 256으로 늘리는 구조를 취하고 있음

### 특징

모든 Conv Layer 다음 Batch Norm을 사용하며 Weight Initialization은 Xavier를 사용함
이 방법은 SGD+Momentum에서 좋은 초기화 성능을 보인다고 함
Learning rate는 Learning rate 스케줄링을 통해서 validation error가 줄어들지 않는 시점에서 조금씩 줄여준다.
minibatch 사이즈는 256이며, weight decay 사용, dropout은 사용하지 않았음

-> 성능 감소 없이 깊은 네트워크를 잘 학습시킬 수 있었으며, backprop 시 네트워크의 gradient flow를 잘 가져감, 네트워크가 깊어질수록 Training Error는 더 줄어들게 됨(깊은 네트워크에서 Train error가 줄어드는 문제 해결)


## 모델 성능 비교

### 계산성능

Y축은 top-1 Accuarcy이고 높을수록 좋음
X축은 연산량으로, 오른쪽으로 갈수록 연산량이 많다.
원의 크기는 메모리 사용량으로, 원이 클수록 덩치가 큰 모델임

- GoogLeNet

  가장 효율적인 네트워크.
  x축의 가장 왼쪽에 붙어있으며 메모리 사용도 적음

### ResNet의 성능 향상 관련 연구

#### 

ResNet Block Path를 조절
directpath를 늘려서 새로운 정보들이 앞으로 더욱 더 잘 전달되고 backprop도 더 잘될 수 있게 개선하였음
이 새로운 block 구조 덕분에 더 좋은 성능을 얻을 수 잇었음

#### Wide resnet networks(2016)

기존의 resnet 논문은 깊게 싸는 것에 열중했지만, 사실 중요한 것은 depth가 아닌 residual이라고 주장했음
residual connection이 있다면 네트워크가 굳이 더 깊어질 필요 엇다고 주장
따라서 residual block을 더 넓게 만들었음. 즉, conv layer의 필터를 더 많이 추가함
기존 ResNEt에 block 당 F개의 filter만 있었다면, 이제는 FxK개의 필터로 구성
각 레이어를 넓ㅁ게 구성했더니 50 레이어만 있어도 152레이어의 기존 resnet보다 더 좋은 성능을 보임

또한 depth 대신에 filter의 width를 늘리면, 계산 효율이 증가한다.(병렬화가 더 잘되기 때문)

#### ResNeXt (ResNet + inEXeption)

여기서도 residual block의 width를 파고듦(filter의 수를 늘리는 것임)
각 residual block 내에 "다중 병렬 경로"를 추가 함.
pathways의 총 합을 cardinality라고 불렀음
하나의 bottleneck resnet block은 비교적 작지만, 이런 thinner blocks를 병렬로 여러개 묶음
ResNeXt와  Wide resnet networks은 Layer를 병렬로 묶어준다는 점에서 Inception Module과도 연관있음
사실 resnext라는 이름 자체가 이를 내포하고 있긴 함

#### stochastic depth(2016)

네트워크가 깊어질수록 vanishing gradient 문제가 발생한다. 깊은 네트워크에선즌 그레디언트를 뒤로 전달할 수록 점점 그레디언트가 작아지는 문제가 있음. 기본 아이디어는 train time에 레이어의 일부를 제거하는 것이다. shotr network이면 트레이닝이 더 잘 될 수 잇끼 때문이다. 일부 네트워크를 골라서 identitiy connection으로 만들어버린다. 이렇게 shrot netwrok를 만들어서 트레인 하면 그레디언트가 더 잘 전달될 수 있게됨. 이것은 매우 효율적인 방법이 도리 수 있으며 dropout과 유사함. test time에서는 full deep 네트워크를 사용함

- cf) NiN(Network in Network, 2014)

MLP conv layer : 네트워크 안에 작은 ㄴ트워크를 삽입하는 것
각 conv layer 안에 MLP(Multi-Layer Perceptron)을 쌓는다 -> FC-layer 몇 개를 쌓는 것임
단순히 conv filter만 사용하지 말고 조금 더 복잡한 계층을 만들어서 activation map을 얻어보자는 아이디어임
NiN은 기본적으로 FC 사용하며 이를 1x1 conv layer라고도 한다.

NiN은 GoogLeNet과 ResNet보다 먼저 Bottleneck 개념을 정립했기 때문에 아주 의미있는 아이디어라고 할 수 있다. GoogLeNet과 ResNet에게 철학적 영감을 주었음

## Non-ResNet

### FractalNet

residual connection이 쓸모없다고 주장함.
따라서 residual connection이 전혀 없음
그들은 shallow/deep network의 정보 모두를 잘 전달하는 것이 중요하다고 생각(fractal한 모습)
FractalNet에서는 shallow/depp경로를 모두 연결하고, train에서는 dropout처럼 일부 경로만 사용, test에서는 모든 경로를 사용한다

### DenseNet(DENSEly Connected Convolutional NETworks)

Dense Block : Main idea
한 레이어가 그 레이어 하위의 모든 레어이와 연결되어 있음
모든 레이어의 출력이 각 레이어의 출력과 concat됨
그리고 이 값이 각 conv layer의 입력으로 들어감.
이 과정에서 dimention을 줄여주는 과정이 포함됨

이러한 dense connection이 기울기ㅣ 소실문제를 해결하고, feature를 더 잘 전달 더 잘 사용할 수 잇께 한다고 주장(각 레이어의 출력이 다른 레이어에서 다시 쓰일 수 있기 때문)

### SqueezeNet

GoogLeNet과 같이 효율성을 중시함
fire module을 도입함
 "squeeze layer"는 1x1 필터들로 구성되고, 이 출력 값이 
1x1/3x3 필터들로 구성되는 "expand layer"의 입력이 됩니다.
SqueezeNet는 ImageNet에서 AlexNet 만큼의
Accuracy를 보이지만 파라미터는 50배 더 적었습니다.
그리고 SqueezeNet을 더 압축하면 AlexNet보다
500배 더 작아지게 됩니다.
SqueezeNet의 용량은 0.5Mb 밖에 안되죠
